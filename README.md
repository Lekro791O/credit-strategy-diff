# credit-strategy-diff

Многопользовательское приложение для анализа изменений в системе принятия
решений (СПР): один и те же заявки прогонены через две версии стратегии
(BEFORE MASTER — прод, AFTER BETA — с изменением), и приложение показывает
аналитику, **что изменилось, у кого и из-за чего** — до выката на прод.

Задача от «Баланс-платформы» (Decision Flow) для хакатона, 6–8 ноября, НИЯУ МИФИ.

Модули 1–2 (сбор заявок и прогон через СПР) уже работают — их результат выдан
как датасет. Этот репозиторий — модули 3 и 4:

- **Модуль 3 — приведение и сравнение:** разбор JSON-ответов в вертикальную
  витрину (~290 тыс. строк на выданном датасете) по контракту
  `task/docs/СХЕМА_ВИТРИНЫ.md`, сравнение срезов с четырьмя типами изменения,
  слой разрезов (одна строка на заявку).
- **Модуль 4 — визуализация в браузере:** сводная таблица с изменяемой
  раскладкой поверх агрегированных фактов counts, отчёт пользовательских
  проверок единой таблицей PASS/FAIL, переход от числа до заявки и атрибута,
  экспорт отчёта в HTML, журнал этапов с провалом в исполняемый код.

## Границы зон (для агентов команды)

| Папка | Зона | Кто |
|---|---|---|
| `pipeline/` | Нормализация ответов, режимы массивов, бакетизация, сравнение, слой разрезов | Codex 1 |
| `mart/` | DuckDB-хранилище витрины + реализация MartAPI (фильтры — `task/checks/README.md`) | Codex 2 |
| `checkrunner/` | Исполнение пользовательских `.py`-проверок, объединение результатов | Codex 2 |
| `api/` | FastAPI: конфигурации прогонов, фоновые задачи, прогресс, workspace | Kimi |
| `frontend/` | Сводная таблица, отчёт проверок, drill-down, экспорт HTML | Kimi |

Правила: схемы данных — только из `task/docs/СХЕМА_ВИТРИНЫ.md` и
`task/checks/README.md`, не менять без синхронизации. Каждый пишет тесты
на свою зону; эталонные CSV в `task/example/` и `task/examples/` — готовые
фикстуры для тестов нормализации. В `main` — только через PR.

## Данные

Датасет (34 МБ, 2002 заявки × 2 среза) в git не входит. Скачать у организаторов
и положить в `data/` так:

```
data/RUN-20260827-0001/
├─ manifest.json
└─ RESULTS/
   ├─ BEFORE_MASTER/<APP_ID>.json
   └─ AFTER_BETA/<APP_ID>.json
```

Для разработки и тестов хватает `task/samples/` (4 заявки в обоих срезах).

## Как поднять (будет заполнено к хакатону)

```bash
# backend
pip install -r api/requirements.txt
uvicorn api.main:app

# frontend
cd frontend && npm install && npm run dev
```

## Проверка точности

Нормализатор должен воспроизвести эталонные CSV на учебных примерах:
`task/example/03..06` и `task/examples/03..06` — входы `01/02` лежат рядом.
На защите приложение прогонят на скрытом датасете: подгонка под выданные
числа не сработает, разбор должен быть общим.
