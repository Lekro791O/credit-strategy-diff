# fix(data): valid-pair cohorts, normalization settings and vertical pivot counts

Демо больше не конструирует строки атрибутов внутри цикла правил: генерируются
JSON-ответы, затем работают обычные нормализация и сравнение. Проверка
уникальности в DuckDB сохранена.

Основная аналитика включает только заявки с корректно обработанной парой
BEFORE/AFTER. Отсутствие, повреждённый JSON, нарушение структуры, ошибки
нормализации/сравнения исключают заявку с диагностикой и отдельными счётчиками.
Новые/потерянные атрибуты корректных пар сохраняются как изменения атрибутов.

Сводная получает вертикальные memberships и SQL counts с SOURCE, SUFFIX,
бакетом выбранного среза и продуктовыми разрезами. Итоги пересчитываются
через DISTINCT APP_ID; cnt_rows отдельно считает уникальные листовые факты.
Drill-down использует те же условия, включая полную ячейку и разрезы продукта.

Добавлены JSON Schema/defaults настроек нормализации и раздельный выбор трёх
процедур. Выбранный facts выполняется; его результат сохраняется и ограничивает
данные сводной/итогов/drill-down. Для пользовательских файлов есть JSON worker
protocol и явный серверный opt-in доверенного локального subprocess-режима;
подключение полноценной песочницы передано участнику 2.

Общие изменения API разрешены владельцем. Frontend по его отдельному указанию
не изменён: участнику 3 необходимо подключить серверные итоги, форму и диагностику.
Точный контракт, поля и запросы: pipeline/INTEGRATION_V2.md.
Схемы task/docs, task/checks и код mart/checkrunner не менялись.

Проверка: полный pytest по tests, pipeline/tests, mart/tests, checkrunner/tests;
эталонные CSV обоих наборов; все реальные task/samples; SQLite/DuckDB,
дубликаты, непарные/повреждённые ответы, фильтры, totals и пользовательские
процедуры. Дополнительно живой HTTP-прогон демо и samples до готового отчёта.
Полный организаторский архив локально отсутствует и не проверялся.
Датасет и runtime-файлы в Git не включены.
