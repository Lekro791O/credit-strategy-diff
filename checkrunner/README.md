# Проверки: запуск, отчёт, изоляция

Пять файлов `task/checks/check_*.py` исполняются **без изменения**.
Для новой проверки достаточно передать код либо путь — registry в коде
приложения изменять не нужно. `CHECK` и строки результата соответствуют
`task/checks/README.md`.

```python
from checkrunner import CheckRunner, CheckSpec, provided_checks

checks = provided_checks() + [
    CheckSpec(code=workspace_code, name="workspace/risk_check.py",
              params={"app_ids_limit": 50}),
    CheckSpec(path="/approved/workspace/custom.py"),
]
report = CheckRunner().run(store, "RUN-001", checks, on_event=publish_progress)
```

`params` объединяются с `CHECK.params` (переданные значения приоритетнее).
Чтение файла не исполняет код в главном процессе. Исполнение уровня модуля,
включая импорт, происходит внутри worker. Уникальность CHECK.id проверяется
в пределах одного отчёта; повторное ID отмечается ошибкой.

## Безопасный режим пользовательского кода

По умолчанию требуется Docker:

```bash
docker build -f checkrunner/Dockerfile -t credit-strategy-checkrunner:local .
```

Контейнер получает только код/параметры и снимок **одного прогона**:
read-only root и входной mount, сеть отключена, capabilities сняты,
`no-new-privileges`, uid 65534, 512 MiB памяти, 1 CPU, не более 64 процессов,
32 MiB tmpfs. Нет mount репозитория, production БД, Docker socket или
переменных окружения приложения. Выполнение ограничено 30 секундами
по умолчанию, вывод — 8 MiB; тайм-аут удаляет контейнер. JSON, не pickle,
используется на границе процесса. Результат повторно валидируется родителем.

Это контейнерная граница доверия, не гарантия против уязвимостей Docker/ядра.
Для публичного сервиса нужны актуальная среда и отдельный worker-host.
Если Docker отсутствует/образ не собран, проверка получает ERROR с
диагностикой; **автоматического перехода к локальному exec нет**.

В этой среде Docker отсутствовал: проверен отказ по умолчанию и локальное
исполнение, но не фактический запуск Docker-образа. Перед включением
пользовательского кода в веб-приложении необходим smoke test контейнера.

## Локальный режим для доверенных проверок

```python
runner = CheckRunner(backend="subprocess", trusted=True, timeout=30)
report = runner.run(store, "RUN-001")  # автоматически пять выданных проверок
```

Локальный процесс изолирует **сбои**, но не защищает машину от вредоносного
Python: код имеет права пользователя ОС, может обращаться к файлам/сети.
Нельзя выставлять `trusted=True` на основании присланного клиентом флага.
Тесты и `mart.demo` используют этот режим для выданного/контролируемого кода.
У этого режима нет жёсткого OS-лимита памяти; тайм-аут и лимит вывода есть.

Каждая проверка имеет отдельный процесс и отдельную копию снимка. Падение,
SyntaxError, исключение, `os._exit`, тайм-аут и неверная схема результата
не останавливают следующие проверки. Родитель завершает группу процессов.
Контракт не предусматривает сторонние зависимости пользовательских проверок:
доступны Python stdlib, DuckDB и код пакетов mart/checkrunner; дополнительные
зависимости нужно заранее установить в контролируемый образ.

## Возвращаемый и сохранённый отчёт

```python
{
    "run_id": "RUN-001",
    "revision": "...",
    "status": "COMPLETED",  # либо COMPLETED_WITH_ERRORS
    "verdict": "PASS",     # FAIL при бизнес-FAIL; None при ошибках без FAIL/без строк
    "rows": [              # только неизменная схема организаторов
        {"LABEL": "...", "SOURCE": "AFTER", "ARGUMENT": "...",
         "CNT": 1, "TOTAL": 100, "METRIC": 0.01, "APP_IDS": ["APP-1"],
         "RESULT": "FAIL", "CONFIDENCE": "LOW"}
    ],
    "executions": [
        {"index": 0, "check_id": "...", "label": "...",
         "status": "COMPLETED",  # ERROR или TIMEOUT для ошибок
         "origin": "...", "code": "...", "sha256": "...", "params": {},
         "duration_seconds": 0.1, "row_start": 0, "row_count": 1,
         "logs": {"stdout": "...", "stderr": "..."}}
    ],
    "diagnostics": []      # например, ошибки callback прогресса
}
```

У ошибочной execution есть `diagnostic` с типом, сообщением и, если доступно,
traceback/logs. У неё нет выдуманной строки PASS/FAIL. UI должен всегда
показывать `status` и ошибки execution, даже если успешные проверки дали PASS.
Ошибка получения источника может произойти до появления check_id/code.
Пустой результат пользовательской проверки сохраняется как COMPLETED с
row_count=0; это не подразумевает PASS. Верхний verdict при пустом отчёте None.

Строки привязаны к execution через `row_start`/`row_count`, без добавления
колонок к контракту организаторов. `CONFIDENCE=LOW` отображается мягко.
APP_IDS должны существовать в текущем прогоне, быть уникальны и не превышать
app_ids_limit/CNT. METRIC — конечное число; SOURCE/RESULT/CONFIDENCE — enum.

Код, origin, параметры и SHA256 сохранены для перехода из журнала в
исполняемый код. Это аудит одного запуска, не система версионирования.
`on_event` получает RUNNING и конечный статус каждой проверки. Его ошибка
сохраняется в diagnostics и не останавливает проверку. Callback отвечает
за сохранение/доставку живого прогресса в API, если это нужно.

Отчёт сохраняется `store.save_check_report` автоматически и читается через
`store.get_check_report`. Повторный запуск заменяет предыдущий отчёт.
Если данные прогона изменились после создания снимка, запись отклоняется
с ValueError: результаты от старой revision не прикрепляются к новым данным.
Проверки одного run_id API-слой должен ставить в очередь: одновременные
повторные наборы на одной revision работают по правилу «последняя запись».

## Экспорт HTML и переходы

```python
from checkrunner.html_report import render_html
from urllib.parse import quote

html = render_html(
    report,
    report_url="https://app.example/reports/RUN-001",
    application_url=lambda app_id: "https://app.example/reports/RUN-001/apps/" + quote(app_id, safe=""),
)
```

Функция возвращает самостоятельный HTML: единая таблица, мягкая подсветка
LOW, диагностика исполнения и ссылки в приложение. Маршруты задаёт
участник 3; существование приведённых путей не предполагается. Пользовательские
строки экранируются, принимаются только абсолютные HTTP(S)-ссылки.
API-слой отвечает за выдачу HTML по ссылке/скачивание и авторизацию переходов.

## Передача и ограничения

Согласованный источник схем — документы организаторов, они не менялись.
Новые Python-интерфейсы предложены в этой ветке; подтверждения участников
1/3 пока нет. HTTP endpoints, интерфейс workspace, фоновые очереди и
подключение к реальному нормализатору находятся вне этой зоны и не менялись.
Смотрите [../mart/README.md](../mart/README.md) для входа/выхода и замеров.
